# FishOJ 换机迁移

当前试用机：阿里云 ECS `http://8.163.87.247`（Ubuntu 22.04 · Hydro 5.0.4 · PM2 + Nix · **非 Docker**）。  
换机是**全量搬家**：用户数据、题库文件、插件、**以及全部密钥**一起从旧机导出、拷到新机恢复。本 Git 仓库仍然**不放真实 Key**（公开仓库已开 GitHub secret scanning，push 会被拒）；密钥打进旧机上的 `fishoj-full-migrate-*.tar.gz`，用 scp 整包搬走。

脚本在 [`server-config/migrate/`](../server-config/migrate/)。导出目录：`/root/fishoj-migrate/`。

---

## 0. 原则

1. **旧机先别关。** 新机验收通过、DNS/IP 切完后再停旧机（建议重叠 48 小时）。
2. **新机规格对齐：** Ubuntu 22.04、x86_64、建议 ≥ 4C8G；评测沙箱在 ARM 上容易缺编译器。
3. **不要把 27017 / 8888 对公网开放。** 安全组只放行 `22`、`80`（有域名再加 `443`）。
4. **密钥必须随包移动，但不进公开 Git。** 导出脚本会收集进程环境、env 文件、PM2、`config.json`（Mongo 密码）、以及库里的小助手 Key。
5. 切 IP 后更新本仓库 README「在线实例」，以及任何答辩材料里的旧地址。

---

## 1. 必须搬走的东西

| 类别 | 位置（旧机） | 不搬会怎样 |
|------|----------------|------------|
| MongoDB `hydro` 库 | 本机 Mongo（PM2 进程 `mongodb`） | 用户、题目、提交、系统设置全丢 |
| Hydro 配置 | `/root/.hydro/config.json` | 连不上库 |
| 插件清单 | `/root/.hydro/addon.json` | 插件未注册 |
| 自研插件代码 | `/root/.hydro/addons/` | IDE / AI / 脚手架不可用 |
| 题目附件与测试数据 | `/root/.hydro/` 下 `file` 等目录 | 题面图片、测评数据 404 / 无法评测 |
| Caddy | 旧机 `~/.hydro` 或 Hydro 自带 Caddyfile | `:80` 反代、SSE 30 分钟超时丢失 |
| LLM 密钥（必须带走） | 见下表 | 助教/分析/小助手失败 |
| 超管账号 | Mongo `user` | 进不了控制面板 |

密钥来源（`01-export-old.sh` 会全部收集进 `secrets.env` + `secrets/`）：

| 密钥 | 旧机位置 | 怎么带走 |
|------|----------|----------|
| `DEEPSEEK_API_KEY` / `BUILTIN_API_KEY` | hydrooj 进程环境、`/etc/environment`、`~/.hydro/*.env` | `secrets.env` |
| 小助手 `FISHOJ_AI_*` / `OPENAI_API_KEY` | 同上；控制面板里的 Key 在 Mongo `system` | `secrets.env` + `mongodump` |
| Mongo 密码 | `/root/.hydro/config.json` 的 `uri` | `hydro-home.tar.gz` 与 `secrets/config.json` |
| PM2 里注入的其它 TOKEN/SECRET | `pm2 prettylist` | `secrets/pm2-prettylist.json` |

Mongo 里一并带走的 FishOJ 集合（`mongodump` 会覆盖，不必单独导）：

- `fish_learning_problem` / `fish_learning_scaffold` / `fish_learning_choice`
- `fish_tutor_session` / `fish_tutor_event`
- `note_assistant_conversation`
- `fish_ai_analysis_cache` / `fish_ai_analysis_daily` / `fish_ai_analysis_log`

**不必从旧机拷：** Hydro 官方包、`node_modules`、Caddy 访问日志、PM2 日志。新机用官方 `setup.sh` 重装核心即可。

## 2. 推荐顺序

```
旧机盘点 → 旧机导出 → 本机暂存备份 → 新机装 Hydro
  → 导入数据/插件 → 配密钥与安全组 → 冒烟测试 → 切流量 → 观察后再关旧机
```

### 2.1 旧机盘点（不改数据）

把 [`00-inventory.sh`](../server-config/migrate/00-inventory.sh) 拷到旧机后：

```bash
scp server-config/migrate/00-inventory.sh root@8.163.87.247:/root/
ssh root@8.163.87.247 "bash -lc 'bash /root/00-inventory.sh'"
```

看：磁盘、`pm2 list`、Hydro 版本、`addon.json`、Mongo 是否能连、`DEEPSEEK_API_KEY` 是否在 hydrooj 进程环境里。

### 2.2 旧机导出

```bash
scp server-config/migrate/01-export-old.sh root@8.163.87.247:/root/
ssh root@8.163.87.247 "bash -lc 'bash /root/01-export-old.sh'"
```

完成后旧机应有类似：

```
/root/fishoj-migrate/
  inventory.txt
  secrets.env                    # 全部 KEY=（权限 600）
  secrets/config.json            # 含 Mongo 密码
  secrets/pm2-prettylist.json
  mongo/                         # mongodump（含 system 里小助手 Key）
  hydro-home.tar.gz
  fishoj-full-migrate-*.tar.gz   # 上面全部打成一份，建议只拷这一个
```

拉回本机（体积可能数 GB；**密钥在包里，不要 git add**）：

```bash
scp root@8.163.87.247:/root/fishoj-migrate/fishoj-full-migrate-*.tar.gz D:/FishOJ-migrate-backup/
```

### 2.3 新机安装 Hydro 核心

在**新机**用 root（与现网一致，先不要 `--no-caddy`，需要 80 端口反代）：

```bash
sudo su
LANG=zh . <(curl https://hydro.ac/setup.sh)
```

装完应能 `pm2 list` 看到 `hydrooj` / `mongodb` / `hydro-sandbox` / `caddy`。  
先浏览器打 `http://新机IP` 确认空白站能开，再导入，避免核心没装好就覆盖配置。

### 2.4 导入

把导出目录和 [`02-import-new.sh`](../server-config/migrate/02-import-new.sh) 拷到新机：

```bash
scp -r D:/FishOJ-migrate-backup root@<新IP>:/root/fishoj-migrate
scp server-config/migrate/02-import-new.sh root@<新IP>:/root/
ssh root@<新IP> "bash -lc 'bash /root/02-import-new.sh /root/fishoj-migrate'"
```

脚本会：停 `hydrooj` → 恢复 Mongo → 解开 `.hydro`（保留新机刚装的官方包）→ 按清单 `hydrooj addon add` → 把 `secrets.env` 写进 PM2 → 重启。

若本地插件比旧机新（例如 `FishOjTheme`、`VipIntroPage` 未上过试用机），导入后再从本仓库覆盖：

```bash
scp -r addons/ProblemIde addons/LearningScaffold addons/AiTutor \
  addons/AiAssistant addons/AiAnalysis addons/OfficialSolution \
  addons/HomePage addons/VipIntroPage addons/FishOjTheme addons/hydroac-client \
  root@<新IP>:/root/.hydro/addons/

ssh root@<新IP> 'bash -lc "
  hydrooj addon add /root/.hydro/addons/VipIntroPage
  hydrooj addon add /root/.hydro/addons/FishOjTheme
  pm2 restart hydrooj
"'
```

目标清单见 [`addon.json.example`](../server-config/addon.json.example)。

### 2.5 密钥（已随包导入）与 Caddy

导入脚本**没有密钥会直接失败**。成功后核对：

```bash
tr '\0' '\n' < /proc/$(pgrep -n -f hydrooj)/environ | grep -E 'KEY|TOKEN'
```

应能看到旧机同名的 `DEEPSEEK_API_KEY` 等（只确认名字存在，不要把值贴到聊天/Git）。

- Caddy：仓库 [`Caddyfile`](../server-config/Caddyfile) 已设 SSE **30 分钟**超时；若被官方默认覆盖，拷回后 `caddy reload`。
- 有域名且备案后再把 `:80` 改成域名以自动 HTTPS。

### 2.6 冒烟测试

新机安全组放行 80 后，用浏览器（硬刷新）检查：

1. 首页能开；能用旧超管登录。
2. `/ide/<一题 pid>` 题面、编辑器、自测、提交、评测结果。
3. AI 助教一轮对话、AI 分析一次（确认 Key 生效）。
4. 控制面板能进；辅助编码 / 题解编辑页能开（若旧机已有数据）。
5. `pm2 list` 四进程 online；`pm2 logs hydrooj --lines 30` 无循环报错。

### 2.7 切流量

1. 新机冒烟通过。
2. 旧机再跑一次 `01-export-old.sh` 做**增量终包**（用户可能还在旧机提交），导入新机覆盖。
3. 把访问地址改成新 IP / 域名；改 README。
4. 旧机改只读或停 `hydrooj`，Mongo 先不停，留 48 小时。

## 4. 常见失败

| 现象 | 处理 |
|------|------|
| 新机装 Hydro 卡在 Nix / 沙箱 | 确认 x86_64；内存不够会编编译器失败，加 swap 或升配 |
| 网站通但提交无结果 | `hydro-sandbox` 是否 online；测例文件是否随 `.hydro` 解开 |
| AI 全挂、做题正常 | 密钥没进 hydrooj 进程：确认导入用了带 `secrets.env` 的包，并 `pm2 restart hydrooj --update-env` |
| 80 能开、SSE 一两分钟断 | Caddy `read_timeout`/`write_timeout` 未按仓库 Caddyfile 设成 30m |
| 登录用户全没了 | 恢复了官方空库、没 `mongorestore`，或 restore 进了错误库名 |
| 插件页面 404 | 未 `hydrooj addon add` 绝对路径，或 `addon.json` 仍指向空目录 |

## 5. 和本仓库的关系

- 插件源码以 Git 为准；**题库与用户数据以旧机 Mongo + 文件为准。**
- 本地未提交内容（分析日志、`FishOjTheme` 等）导入后需再 `scp` 一次最新 `addons/`。
- 正式环境以后若改 Docker，仍建议先按本文「导出 Mongo + `.hydro` 文件」同一套数据，再装进容器。
